# ConHub. v0.5.4 validation — 2026-11-03

Status: review candidate, not a stable release. The installed application and user game projects were not replaced.

## Confirmed causes

The supplied November 1 logs contain `413 request_body_too_large` with a 10,485,760-byte limit, closed stdio pipes and missing response IDs. They do not record the offending tool's name, arguments or response. Unbounded scene breadth/value encoding, missing-ID acceptance and drip-feed timeout escape were independently reproduced in the source fixtures; attribution of the historical oversized response to one particular tool remains unproven.

## Implementation

- Godot: bounded scene pages and property encoding; filters, subtree selection, continuation metadata and scene identity. Engine response 384 KiB, Python bridge frame 512 KiB, final serialized MCP result 1 MiB including duplicated/escaped content. Request-scoped sockets, strict IDs, overall deadlines and cancellation isolate failed calls. Adaptive capture retains aspect ratio. The launcher prioritizes its adjacent source over an obsolete editable-install mapping.
- ReConnect: opt-in observation/recovery/waiting, nine attempts in three cycles of Restart, Restart, Stop/Doctor/Start. Five-second confirmation, ten-second retry interval, immediate success reset, manual yellow rearm and cancellation on disable. Fresh critical Godot events prompt a status confirmation; tool errors/idle time/old log files do not trigger recovery. All Godot commands/project switches share the existing adapter's operation gate; fallback operations have a 90-second deadline after acquiring it.
- NVIDIA: retained PR #18's installed NVIDIA relay and dedicated `constantine-nvidia` profile design. Replaced TCP-only readiness with bounded MCP initialize/tools-list, negotiated protocol, JSON-RPC response correlation for JSON/SSE, session cleanup and serialized ownership-safe controls. ConHub. never terminates NVIDIA App's external process or exposes its loopback HTTP listener publicly.
- UI: ConHub. display name, requested text colors, enlarged logo, Home/project selector above the main column, Jensen Utility card and persistent collapsed Godot header controls. Source PNGs are bundled. Separate off/green/red/yellow render evidence is recorded; colored renders use injected display states, not a claimed live outage.
- Windows: constant tray GUID and AppUserModelID; no native icon in smoke/isolated fixtures, idempotent registration and cleanup, Explorer restart handling. History is read-only until an individually confirmed exact-entry deletion, with ownership checks, revalidation and typed backup. Unknown historical paths and current identity remain protected. No global cache or promotion preferences are reset.
- Compatibility: preserve `ConstantineHub.exe`, updater/archive names, installation destinations, configuration keys, inbox path and tunnel profiles. App and updater both report 0.5.4. The workflow pins the actual v0.3.1 fixture and requires explicit manual stable publication.

## Remaining acceptance

- The user supplied the dedicated NVIDIA tunnel ID. Its local `constantine-nvidia` profile is now configured with loopback health port 8083 and an environment key reference; native Doctor succeeded. Ten explicit workstation assertions verified actual ConHub-owned Start, repeated Start, external ownership protection, Restart, Stop, native health/readiness and that NVIDIA App remains available. Full remote agent/tool-call acceptance through this particular tunnel remains separate from local/owned readiness. No credential values belong in the repository or chat.
- A normal production tray registration and repeated launches/updates at the final installation path have not been exercised. The fake-shell lifecycle tests and no-tray smoke/history checks do not certify Windows' historical-record behavior for a new normal registration. Unsigned GUID icons remain bound to their executable path; moving the application may prevent registration.
- No live user editor/game end-to-end test, final artistic/UI acceptance or stable release approval is claimed. Synthetic engine/TCP and actual MCP transport tests are separate evidence. Hosted CI may explicitly skip the engine fixture without `GODOT_EXECUTABLE`; it still runs socket/result-budget and actual stdio tests.

Hosted CI run #60 exposed an asynchronous file-inbox UI race: without a WinForms synchronization context, import completion updated controls on a worker thread while the smoke test closed the form. A deterministic cross-thread regression reproduced it. Completion is now dispatched to the owning form, and the real drop test waits for the import task before closing. The subsequent hosted run is tracked in PR #18.
